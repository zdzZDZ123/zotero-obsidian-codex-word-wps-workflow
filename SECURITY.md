# Security policy

## Never publish

- Zotero databases, storage folders, private group libraries, or copyrighted PDFs;
- Zotero, Obsidian, GitHub, or Codex credentials and session state;
- API keys, OAuth client secrets, cookies, passwords, or `.env` files;
- the bearer token generated by `llm-for-zotero` for its local MCP endpoint;
- machine-specific home paths, device identifiers, and private Vault content.
- exported similarity reports, normalized findings, revision ledgers, recheck
  results, and unpublished manuscript copies.

The local Zotero MCP endpoint is loopback-only in this workflow. Its bearer token must be generated independently on every computer through the plugin UI and must never be copied into an issue, log, screenshot, or repository.

## Before publishing a change

Run:

```powershell
pwsh ./scripts/validate-repo.ps1
```

Then review the full staged diff. Automated checks reduce risk but cannot prove that a note or PDF is safe to publish.

## Reporting a vulnerability

Do not open a public issue containing a live credential. Revoke or rotate it first, remove it from Git history, and then open a sanitized issue describing only the affected component and reproduction conditions.
