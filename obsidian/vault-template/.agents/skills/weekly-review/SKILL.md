# Weekly Review

1. Read `AGENTS.md`, `Home.md`, active projects, `00-Inbox/_Inbox.md`, `90-System/Review Queue.md`, and notes changed in the last seven days.
2. Create `90-System/Reviews/YYYY-Www Weekly Review.md` using `99-Templates/Weekly Review.md`.
3. Summarize completed work with links. Do not infer completion from activity alone.
4. Ensure every active project has one concrete next action; flag blocked or stale projects.
5. List unprocessed inbox items and recommend the smallest useful processing batch.
6. Identify knowledge that was actually used, plus outputs or decisions that should feed back into evergreen notes.
7. Record repeated friction in `90-System/Review Queue.md`.
8. Make at most one small, reversible improvement to a template, skill, index, or instruction when evidence supports it. Append the change, reason, and expected effect to `90-System/Evolution Log.md`.

Never delete, bulk move, or weaken provenance rules during review. Ask before structural changes that would break links or alter established organization.
