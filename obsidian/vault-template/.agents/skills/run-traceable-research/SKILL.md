# Run Traceable Research

Use this skill only as the storage and handoff layer. Delegate research design, literature synthesis, analysis, drafting, review, and integrity gates to `$academic-research-suite`; do not restate or fork that suite.

1. Read `AGENTS.md`, `10-Projects/_Projects.md`, and search for an existing project with the same outcome. Resume it when present; otherwise use `$start-project` to create one.
2. Inventory the Zotero evidence before choosing a method. Record library scope, available PDFs, DOI or other stable identifiers, citation keys, and read dates. Treat a small library as seed evidence, not a complete corpus, and state coverage gaps.
3. Route a broad topic to `$academic-research-suite` Socratic scoping. Route a clear research question or an explicitly requested full pipeline to its appropriate academic workflow.
4. Keep the project note as the control record: research question, study type, constraints, target outlet, source inventory, phase locations, decisions, current gate, and one concrete next action. Verify current journal or reporting requirements from primary sources when they affect the deliverable.
5. Preserve durable results in the vault:
   - Capture source material through `$capture-source` when it belongs in `00-Inbox`.
   - Distill genuinely reusable ideas through `$distill-knowledge`.
   - Store the evidence map, search coverage, inclusion and exclusion rules, inference limits, and freeze dates in `30-Resources`.
   - Store the final manuscript index and reproducibility-package index in `50-Outputs`.
   - Link large working files outside the vault instead of copying unstable intermediates into it.
6. Enforce provenance at each handoff. Keep claim-to-source links, search and access dates, exclusion reasons, dataset or artifact versions, and explicit distinctions between verified full text, abstract-only evidence, and unverified leads.
7. Stop rather than invent missing data, author identity, affiliations, ORCID, funding, conflicts, ethics determinations, licenses, credentials, independent-reviewer actions, or acceptance claims. Mark these as human completion gates.
8. Complete only when the requested manuscript or report, citations, supporting material, reproducibility artifacts when applicable, and a clear limitations record exist. Create an external delivery copy only when requested.
9. Close the loop in one pass: update the project note, `10-Projects/_Projects.md`, and the project board to the same status; link the final output; distill only lessons with durable value; record any system change in `90-System/Evolution Log.md`.

If evidence is insufficient for the requested design, finish with a feasibility finding and the smallest evidence-acquisition plan rather than forcing a paper.
